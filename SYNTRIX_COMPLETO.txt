================================================================
  1. O QUE E O SYNTRIX
================================================================

O Syntrix NAO e um bot de trading simples. E um MOTOR PROBABILISTICO
QUANTITATIVO ADAPTATIVO orientado a eventos, com foco em:

- Motor de decisao: compara oportunidades e seleciona a melhor
- Multi-asset scanning: escaneia dezenas de ativos simultaneamente
- Meta scoring: modelo multiplicativo de confianca probabilistica
- Contexto inteligente: hard blocks vs soft blocks, confidence model
- Thresholds adaptativos: ajustam por horario, regime, ativo, OTC
- Asset DNA: perfil comportamental por ativo com auto-ajuste
- Market phase detection: 10 fases granulares de mercado
- Strategy health: deteccao de degradacao de edge, pesos adaptativos
- Microestrutura: analise de qualidade de price action
- Gestao de risco: stops, drawdown, cooldown, safe mode
- Single position execution: apenas UMA posicao aberta por vez
- Observabilidade total: decision trace, diagnostic mode, block reasons
- Replay: reproducao completa de sessoes via event sourcing
- Analytics profissional: monte carlo, equity smoothness, edge stability
- Arquitetura desacoplada: modulos independentes via EventBus

Filosofia central:
"Selecionar melhor e mais importante do que prever melhor."

O Syntrix NAO age como "sistema que procura sinais".
Ele age como "motor probabilistico que procura assimetrias estatisticas".

Pipeline v2.0:
MULTI-ASSET SCAN -> RAW SIGNALS -> META SCORE -> OPPORTUNITY RANKING
-> DECISION ENGINE -> RISK ENGINE -> EXECUTION -> RESULT

  IDLE -> SCANNING -> WAITING_CONTEXT -> READY -> EXECUTING -> COOLDOWN -> SCANNING


================================================================
  5. CONTEXT GATE v2.0 — CONFIDENCE MODEL
================================================================

O ContextGate usa modelo de confianca probabilistica (v2.0).
NAO e mais binario ALLOW/BLOCK.

MODELO:
  - HARD BLOCKS: bloqueio imediato, confidence = 0
    broker offline, websocket morto, drawdown critico, safe mode
  - SOFT BLOCKS: reduzem confianca (multiplicadores 0.0-1.5)
    volatilidade alta, score marginal, payout medio,
    latencia moderada, sessao fraca
  - CONFIDENCE MODIFIERS: cada filtro retorna modifier + severity
  - THRESHOLD ADAPTATIVO: ajusta por regime, horario, ativo, OTC

  11 Verificacoes:
  1. Payout minimo         Payout >= threshold (65% no leve)
  2. Sessao valida          OTC: sempre permitido (24h)
  3. Filtro de noticias     Bloqueia proximo de noticias
  4. Regime de mercado      Bloqueia regimes instaveis
  5. Detector de spikes     Bloqueia candles anomalos
  6. Latencia do broker     Reduz confidence se alta
  7. Cooldown               Tempo minimo entre trades
  8. Rate limit             Max trades por hora
  9. Drawdown               Hard block se > threshold
 10. Saude do broker        Hard block se offline
 11. OTC Behavior           Analisa qualidade OTC

BLOCK REASONS PADRONIZADOS:
  LOW_SCORE, LOW_PAYOUT, REGIME_UNSTABLE, OTC_NOISE,
  SPIKE_DETECTED, SAFE_MODE, LATENCY_HIGH, COOLDOWN,
  DRAWNDOWN_LIMIT, BROKER_UNHEALTHY, SESSION_BLOCKED,
  MAX_TRADES

DECISION TRACE:
  Toda decisao gera trace completo com 8 etapas:
  SCAN -> REGIME -> STRATEGY -> SCORE -> CONTEXT -> RISK -> EXECUTION -> RESULT
  Cada etapa registra: timestamp, duracao, score, confidence,
  threshold, motivo, decisao, correlation_id

DIAGNOSTIC MODE (python main.py --diagnostic):

  SIGNAL: CALL

================================================================
  7. ESTRATEGIAS DE TRADING
================================================================

  1. TREND PULLBACK (trend_pullback.py)
     - Opera a favor da tendencia durante pullbacks
     - Regime compativel: trend
     - Usa EMA, RSI, ATR para confirmar

  2. RANGE REVERSAL (range_reversal.py)
     - Opera reversao em mercado lateral
     - Regime compativel: range
     - Usa Bollinger Bands, RSI, Stochastic

  3. BREAKOUT (breakout.py)
     - Opera rompimentos de niveis importantes
     - Regime compativel: range, low_volatility
     - Usa ATR, volume, suporte/resistencia

  4. MOMENTUM (momentum.py)
     - Opera movimentos fortes de momentum
     - Regime compativel: trend, high_volatility
     - Usa MACD, ADX, RSI

Cada estrategia:
  - Retorna score (0.0 a 1.0)
  - Retorna confianca
  - Retorna direcao (CALL/PUT)
  - NUNCA executa ordem diretamente
  - E avaliada pelo ScoringEngine antes de executar

[2026-05-09 21:30 UTC] v2.1.0 — CALIBRACAO OPERACIONAL + SHADOW MODE
  Sistema calibrado para OPERAR. De "arquitetura impressionante" para
  "motor funcional, ativo, calibrado e adaptativo".

  PROBLEMA RESOLVIDO:
    O sistema estava excessivamente conservador e NAO fazia entradas.
    Modelo multiplicativo de confianca (mod1 x mod2 x mod3...) produzia
    valores muito baixos. Multiplos filtros soft com penalidades agressivas
    bloqueavam praticamente todos os trades.

  SOLUCOES IMPLEMENTADAS:

  1. CALIBRACAO DE FILTROS:
    - ContextGate: modifiers suavizados (0.85-0.95 em vez de 0.50-0.70)
    - CAUTION agora permite trades (antes bloqueava)
    - Meta Scoring: media geometrica em vez de multiplicacao bruta
    - OTC Analyzer: usa min(modifiers) em vez de multiplicar todos
    - Decision Engine: thresholds reduzidos (confidence 0.30, meta 0.35)
    - Context base_threshold: 0.50 -> 0.40
    - Scoring min_final_score: 0.50 -> 0.40

  2. SHADOW MODE (execution/shadow_mode.py):
    - python main.py --shadow --diagnostic
    - Simula TODAS as entradas sem enviar ordem real
    - Registra tudo: ativo, direcao, estrategia, regime, fase, score,
      meta_score, confidence, payout, volatility, OTC quality, etc
    - Salva em CSV (data/shadow/shadow_YYYYMMDD.csv)
    - Gera relatorio automatico ao parar (data/shadow/report_*.txt)
    - Registra sinais bloqueados tambem para analise
    - Objetivo: gerar milhares de samples rapidamente

  3. RELATORIO 'POR QUE NAO OPEROU' (analytics/operation_report.py):
    - block_rate_by_reason: frequencia de cada motivo de bloqueio
    - allow_rate: taxa de sinais permitidos
    - confidence_distribution: distribuicao de confianca
    - Recomendacoes automaticas quando sistema muito restritivo
    - Impresso automaticamente ao parar o sistema

  4. PROBABILITY CALIBRATION (analytics/calibration.py):
    - Converte scores heuristicos em probabilidade REAL
    - confidence=0.72 -> "historicamente 64% winrate"
    - Calibration curves por bucket (0.0-1.0, step 0.10)
    - Rolling expectancy por bucket
    - Detecta over/underconfidence
    - Calcula optimal threshold automaticamente
    - Relatorio formatado

  5. EDGE DISCOVERY ENGINE (analytics/edge_discovery.py):
    - Descobre melhores ativos/horarios/fases/estrategias
    - Analisa por dimensao: asset, strategy, regime, phase, hour
    - Analisa combinacoes: asset+regime, strategy+phase, asset+hour
    - Ranking por expectancy
    - Confianca estatistica baseada em sample size
    - Relatorio formatado com top edges

  6. ADAPTIVE LEARNING LAYER (analytics/learning.py):
    - Ajuste automatico de pesos de estrategia
    - Ajuste de threshold por ativo (bons=menor, ruins=maior)
    - Correcao de score bias (overconfidence/underconfidence)
    - Recalibracao periodica (a cada 20 trades)
    - Learning rate configuravel
    - Estado persistente durante sessao

  ARQUIVOS NOVOS (4 modulos):
    execution/shadow_mode.py       Shadow Mode (simulacao sem ordem real)
    analytics/calibration.py       Probability Calibration Engine
    analytics/edge_discovery.py    Edge Discovery Engine
    analytics/learning.py          Adaptive Learning Layer
    analytics/operation_report.py  Operation Report (POR QUE NAO OPEROU)

    context/otc_analyzer.py  min(modifiers), penalidades reduzidas
